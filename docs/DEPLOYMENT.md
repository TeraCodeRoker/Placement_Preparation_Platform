# Deployment runbook (Render free tier)

Everything is deploy-ready (`render.yaml`, `.env.example`, migrations). The steps
below are **yours to perform** — they require your accounts and keys, which I
can't create or enter for you.

## 0. Prerequisites (accounts + keys)
1. **Rotate the leaked Gemini key** (it was in the source archives) and create a
   fresh one at <https://aistudio.google.com/app/apikey>.
2. **Code execution — nothing to do.** It runs on the free, keyless Paiza public
   runner (`api_key=guest`), configured in `render.yaml`. No account, no card.
   Judge0 is *not* used by default (its RapidAPI tier is metered/paid) and the
   public Piston API went whitelist-only in Feb 2026 — both remain switchable via
   `EXECUTION_PROVIDER` if you ever self-host or buy a plan. See
   [ADR-020](ADRS/020-free-code-execution.md).
3. **Database** — create a **Neon** project (always-free) and copy its connection
   string. **Paste it exactly as Neon gives it** — `postgresql://…?sslmode=require`
   parses straight to Django's postgres backend, `sslmode` included; no rewriting
   needed. (`postgres://` works identically, and an `+asyncpg` suffix left over
   from the FastAPI era is normalized away.) Render free Postgres is the
   documented alternative — see ADR-002's renewal runbook (expires in 30 days).
   Full walkthrough: [NEON_SETUP.md](NEON_SETUP.md).
4. A **GitHub** repo with this code, and a **Render** account.

## 1. Provision from the Blueprint
- Push to GitHub. In Render: **New → Blueprint**, point it at the repo. Render
  reads `render.yaml` and creates `prepstack-api` (web) + `prepstack-web` (static).

## 2. Set secrets (Render dashboard → prepstack-api → Environment)
| Var | Value |
|---|---|
| `DATABASE_URL` | the Neon string, pasted verbatim (`postgresql://…?sslmode=require`) |
| `GEMINI_API_KEY` | your rotated key |
| `ALLOWED_ORIGINS` | `https://prepstack-web.onrender.com` |
| `ADMIN_BOOTSTRAP_EMAIL` | the email you'll register as admin |

`GEMINI_API_KEY` is the **only** paid-service-adjacent secret, and its tier is
free. `JWT_SECRET` and `DJANGO_SECRET_KEY` are auto-generated by Render;
`APP_ENV=prod`, `GEMINI_MODEL`, `EXECUTION_PROVIDER`/`PAIZA_*` come from
`render.yaml` (no key). If a required prod
secret is missing, the app **fails fast at boot** rather than serving broken —
check the logs.

## 3. Deploy
- Render builds the backend (`pip install` + **`python manage.py migrate`**
  creates the schema) and serves via **Gunicorn**; the static site builds and
  deploys to the CDN. First request after 15 min idle cold-starts (~30–60 s) —
  the frontend shows a "waking up" banner.
- Optional: seed demo data once via the Render **Shell** —
  `python manage.py seed` (set `SEED_PASSWORD` first to also create demo logins).

## 4. Verify (the §9.2 manual checklist)
- `GET https://prepstack-api.onrender.com/health` → `{"status":"healthy"}`.
- `GET …/health/detailed` → `db: up`, `gemini: configured`,
  `execution_provider: paiza`, `execution: ready`.
- Open the static site → run the `docs/TESTING.md` checklist (guest interview,
  **OA run+submit executing real code**, register→claim, admin notes, resume
  upload, degraded-mode banner).

## Notes
- **Rewrite proxy:** the static site proxies `/api/*` and `/health` to the
  backend so the browser sees one origin (SameSite=Lax refresh cookie works). If
  your Render plan can't rewrite to an external service, set `VITE_API_BASE` to
  the backend origin and switch the refresh cookie to `SameSite=None; Secure`
  (cross-site) — CORS is already locked to `ALLOWED_ORIGINS` (ADR-004).
- **Rollback:** a failed deploy leaves the previous good deploy live (Render
  default). **Auto-deploy:** merges to `main` redeploy automatically.
- **Postgres renewal (if using Render Postgres):** see ADR-002 — provision a new
  free instance before day 30, `pg_dump`/`pg_restore`, update `DATABASE_URL`.
